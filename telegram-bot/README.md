# Telegram-бот VisaMB для AWS Lambda

Бот задаёт вопросы, показывает ответы и отправляет заявку получателю только
после нажатия **«Отправить заявку»**. Клиенту не нужно ничего привязывать.
Имя в Telegram, ник (если есть) и числовой Telegram ID берутся автоматически.

Все файлы этой реализации находятся в `telegram-bot/`. Код сайта не изменяется.

## Самый простой запуск: AWS CloudShell

1. Создайте бота через **@BotFather → /newbot**, получите токен.
2. Войдите в AWS Console и откройте **CloudShell** в нужном регионе.
   В CloudShell уже доступны Python и авторизованный AWS CLI v2.
3. Выполните:

```sh
git clone https://github.com/Sergisaev/VisaMB.git
cd VisaMB
python3 telegram-bot/deploy.py
```

Скрипт попросит **только токен**; ввод скрыт. Он проверит токен, создаст стек
CloudFormation, дождётся запуска ресурсов, зарегистрирует webhook и выведет
ссылку на бота. Docker, SAM CLI, установка Python-пакетов и сборка ZIP для этого
способа не требуются.

При отсутствии настроенного региона используется `eu-central-1`. Другой регион:

```sh
python3 telegram-bot/deploy.py --region eu-west-1
```

4. Откройте полученную ссылку **с аккаунта @maa_ri888** и один раз нажмите
   **Start**. Бот подтвердит получение заявок. Это единственное служебное действие
   получателя, клиентам оно не показывается.
5. Для самостоятельной проверки в этом же аккаунте отправьте **/request**.
   Другой клиент просто нажимает Start и проходит опрос.

AWS-пользователю, который запускает установку, нужны права CloudFormation,
Lambda (включая Function URL), IAM (создание роли и PassRole), DynamoDB, SQS и
CloudWatch Logs. Учётные данные AWS не помещаются в код: CloudShell использует
вашу текущую сессию. Регион и стек скрипт показывает перед созданием.

Если создание стека завершилось ошибкой, её причина доступна в
**CloudFormation → visamb-telegram-bot → Events**. Стек в состоянии
`ROLLBACK_COMPLETE` нельзя обновить обычным update: сначала разберите причину
ошибки и удалите неудачный стек через CloudFormation либо выберите новое имя
с `--stack-name`.

## Настройки и смена получателя

Токены в исходниках и в `settings.example.json` оставлены пустыми:

```python
BOT_TOKEN = ""
WEBHOOK_SECRET = ""
RECIPIENT_USERNAME = "maa_ri888"
RECIPIENT_CHAT_ID = ""
```

Для удобной смены настроек создайте локальный файл:

```sh
cp telegram-bot/settings.example.json telegram-bot/settings.local.json
```

Пример его содержимого:

```json
{
  "bot_token": "",
  "webhook_secret": "",
  "recipient_username": "maa_ri888",
  "recipient_chat_id": "",
  "region": "",
  "stack_name": "visamb-telegram-bot",
  "data_retention_days": 30
}
```

- `bot_token` можно оставить пустым: установщик спросит его скрытым вводом.
- `webhook_secret` можно оставить пустым: установщик создаст случайный секрет и
  сохранит его в `.deploy-state.json` для следующих обновлений.
- Для другого получателя поменяйте **`recipient_username`**, снова запустите
  установщик и нажмите Start с нового аккаунта получателя.
- **`recipient_chat_id`** — альтернативная настройка, если уже известен числовой
  ID личного чата получателя. При заполнении она имеет приоритет перед ником;
  этот аккаунт также должен ранее запустить бота.

`settings.local.json`, `.deploy-state.json`, ZIP и собранные шаблоны исключены
из Git. Токен не записывается установщиком в `.deploy-state.json`, не выводится
в терминал и не передаётся значением в аргументах AWS CLI. CloudFormation-параметры
токена и webhook-секрета имеют `NoEcho`.

Telegram Bot API не отправляет личное сообщение произвольному `@username`.
Поэтому бот запоминает числовой ID получателя, когда тот запускает его.
Дальше доставка идёт по этому ID и продолжает работать при изменении ника
того же аккаунта. Смена `recipient_username` в настройках означает выбор
нового получателя. У клиентов никакой регистрации получателя нет.

Переменные окружения `BOT_TOKEN`, `WEBHOOK_SECRET`, `RECIPIENT_USERNAME`,
`RECIPIENT_CHAT_ID` имеют приоритет над файлом настроек. Константы в начале
`lambda_function.py` используются как исходные значения.

## Вопросы клиента

1. Имя — вручную или кнопкой «Использовать имя из Telegram».
2. Направление: Шенген, Кипр, Япония, США, Канада или «Пока выбираю».
3. Гражданство и страна проживания.
4. Цель поездки.
5. Примерные сроки и длительность поездки.
6. Предыдущие визы и отказы.
7. Необязательные дополнения.

Если у аккаунта нет ника, бот дополнительно попросит телефон, email или другой
Telegram-ник, чтобы консультант мог ответить. Выбора города нет: в приветствии
указана работа с заявлениями по Москве и Санкт-Петербургу онлайн.

Перед отправкой доступны изменение любого ответа и отмена. В готовой заявке
есть номер, дата UTC, имя, ник, Telegram ID, контакт и все ответы. У получателя
также появляется кнопка открытия профиля клиента. По США и Канаде бот явно
указывает формат консультации.

## Что создаётся в AWS

Один стек CloudFormation содержит:

- **Lambda на Python 3.13**, обработчик `index.lambda_handler`;
- **Function URL** — HTTPS-адрес webhook с проверкой секретного заголовка Telegram;
- **DynamoDB** — ответы, заявки, получатель и прогресс отправки;
- **SQS FIFO** — последовательная обработка сообщений каждого клиента;
- **очередь ошибок (DLQ)** — обновления, не обработанные после пяти попыток;
- роль IAM и журналы CloudWatch Logs с хранением 14 дней.

Lambda запускается по событиям; постоянно работающий процесс не нужен. Тарифы
AWS применяются к использованным ресурсам, бесплатная работа не предполагается.
При обычной настройке не добавляйте функцию в частную VPC без выхода в интернет:
ей нужен HTTPS-доступ к `api.telegram.org`.

Webhook подтверждает приём после записи обновления в очередь. Ответы и исходящие
сообщения сохраняются атомарно, так что холодный старт Lambda не сбрасывает
опрос. Повторы обновлений распознаются, а после сбоя продолжается незавершённая
отправка. Клиент видит «отправлена» только после принятия уведомления Telegram.
При редком обрыве соединения после принятия сообщения Telegram, но до получения
ответа ботом, повтор уведомления возможен; номер заявки остаётся тем же.

Записи опросов и заявок хранятся 30 дней по умолчанию; удаление DynamoDB TTL
выполняется AWS не мгновенно. Привязка получателя не истекает. При удалении стека
таблица DynamoDB сохраняется (`Retain`); её удаляют отдельно, если данные больше
не нужны. Неразобранные обновления в DLQ хранятся до 14 дней и могут быть
возвращены в исходную очередь через **SQS → очередь ошибок → Start DLQ redrive**.
Данные клиентов и токены в журналы приложения не выводятся.

## Повторное развёртывание

```sh
cd ~/VisaMB
git pull --ff-only
python3 telegram-bot/deploy.py
```

Сохраните прежнее имя стека, регион и `.deploy-state.json`. Таблица с ответами
останется, webhook будет обновлён; ожидающие сообщения Telegram не удаляются.
Скрипт также корректно обрабатывает повторный запуск без изменений ресурсов.

## Подключение кнопок сайта

После запуска установщик покажет реальный адрес `https://t.me/ИМЯ_БОТА`.
Его нужно записать в `TELEGRAM_BOT_URL` в `index.html` и отправить изменение
в GitHub. Сейчас эта переменная сайта и сам файл сайта оставлены без изменений:
реальный ник бота ещё не задан.

## Сборка для загрузки вручную

```sh
python3 telegram-bot/deploy.py --build-only
```

Команда работает без AWS и токенов. Результат в `telegram-bot/dist/`:

- `cloudformation.json` — полный шаблон с уже встроенным кодом; его можно
  загрузить в CloudFormation Console. Сырой `template.json` из репозитория —
  входной шаблон установщика, его напрямую не разворачивают.
- `bot.zip` — только `lambda_function.py`. Для отдельной ручной загрузки ZIP
  обработчик будет `lambda_function.lambda_handler`; инфраструктуру, переменные
  окружения и права в таком случае настраивают отдельно.

Основной способ через CloudShell создаёт всё автоматически и не требует ZIP.
В Lambda нет сторонних зависимостей: используются стандартная библиотека Python
и boto3 из стандартного управляемого runtime AWS.

## Тесты

Базовые тесты работают со стандартным Python. Для полной проверки с эмуляцией
API DynamoDB/SQS и проверкой схемы CloudFormation:

```sh
python3 -m venv /tmp/visamb-bot-tests
/tmp/visamb-bot-tests/bin/pip install -r telegram-bot/requirements-dev.txt
/tmp/visamb-bot-tests/bin/python -m unittest discover -s telegram-bot/tests -v
python3 telegram-bot/deploy.py --build-only
/tmp/visamb-bot-tests/bin/cfn-lint telegram-bot/dist/cloudformation.json
```

Тесты проверяют полный опрос и подтверждение, отсутствие ника, редактирование,
отмену, раздельные сессии клиентов, смену получателя, секрет webhook, повторы,
сбои доставки, холодный старт, транзакции и сборку. Реальные сообщения Telegram
и ресурсы AWS в тестах не создаются. Боевой запуск проверяется после ввода
настоящего токена и развёртывания в вашем AWS.
